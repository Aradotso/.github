# Contributing to Ara

Ara is built by a small founder-led team, product and engineering leads, and trusted contributors. Founders Sven Myhre and Adi Singh retain final accountability for company-level direction, while leads own day-to-day decisions in their areas and contributors help move scoped work forward. This guide explains how contributors can participate and how project access grows with demonstrated judgment.

## Contributor Path

Everyone starts as a contributor. Contributors can open issues, propose changes, review public discussions, and submit pull requests. Contributors are expected to keep discussions specific, document the user impact of proposed changes, and ask for review from the relevant lead when a change affects product direction, security, infrastructure, or release timing.

## Team Roles and Maintainer Levels

Ara uses three project access levels beyond general contribution: triage, committer, and maintainer. Access is granted by maintainers based on repeated high-quality work, good judgment, and alignment with Ara's product and security standards.

### Triage access

Triage access is for trusted contributors and team members who help keep the project organized. People with triage access can label issues and pull requests, reproduce reports, request missing information, link related work, and close issues that are duplicates, stale, invalid, or already resolved.

Triage decisions are limited to project hygiene. Triage contributors can decide whether an issue has enough information to proceed, whether it belongs in the current project, and which lead or area should own it. They cannot merge code, approve releases, change security policy, or make product commitments on behalf of Ara.

### Committer access

Committer access is for contributors and leads who have shown consistent technical judgment in a specific area of the codebase. Committers can merge pull requests when the change is reviewed, tests or manual validation are documented, and the change is within an area they understand.

Committers can make implementation decisions for scoped fixes, refactors, documentation updates, and product improvements that match an already agreed direction. They should escalate before merging changes that affect billing, security posture, user data, infrastructure, public API behavior, release timing, or company-level product positioning. When in doubt, a founder or relevant lead should approve before merge.

### Maintainer access

Maintainer access is held by Ara's founders and designated leads who are accountable for the project as a whole. Maintainers can cut releases, manage repository members and permissions, approve security policies, accept or reject major technical direction, and make final calls when contributors disagree.

Maintainers decide project-wide standards, release readiness, incident response, security handling, access changes, and cross-team priorities. Founders retain final authority for company-level decisions, including security policy, public commitments, membership, and release strategy.

## Escalation Path

The normal path is contributor to triage to committer to maintainer. A contributor becomes eligible for triage access after repeatedly filing useful issues, improving documentation, helping reproduce bugs, or providing reliable review context. A triage contributor becomes eligible for committer access after submitting and reviewing changes that are merged cleanly, tested appropriately, and aligned with the relevant area lead's expectations.

Committers become eligible for maintainer access only when they are already acting as area owners: they review others' work, handle ambiguous tradeoffs, communicate clearly across the team, and can be trusted with releases, membership, and security-sensitive decisions. Maintainer access is granted by existing maintainers, with founder approval for any change that affects repository ownership, security policy, or company-level authority.

Escalations should be explicit. Contributors escalate to the relevant lead when a decision changes product behavior, affects users or customer commitments, touches security or privacy, alters infrastructure or billing, or creates disagreement between reviewers. Leads escalate to founders when a decision affects company strategy, release risk, external messaging, security posture, or team membership.

## Decision Rights

Contributors can decide how to frame an issue, propose an implementation, and update their own pull requests in response to review.

Triage contributors can decide labels, issue status, duplicate closure, ownership routing, and whether a report needs more information before engineering work begins.

Committers can decide whether scoped code, documentation, and test changes are ready to merge when they satisfy review, validation, and ownership requirements.

Maintainers can decide releases, repository permissions, security policy, architectural direction, disputed reviews, and exceptions to the normal contribution process.

Ara's founders and designated leads use these roles to keep the project moving while preserving clear accountability for user trust, product quality, and team access.
