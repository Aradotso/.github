# Ara Public Product Roadmap

Ara is building the agent workspace for people who want dependable automation on their own Mac: power users who automate daily work, developers who want coding agents with real context, and founders turning repeated operating workflows into reusable agents.

This roadmap is public so users can see where the product is headed. It complements Ara's public product roadmap at [ara.so/roadmap](https://ara.so/roadmap) with a focused view for the profile audience. Timelines are directional and may shift as we learn from real agent runs, customer feedback, and platform reliability work.

## Now

These are the product areas we are actively tightening now.

- Coding agents in isolated worktrees that can inspect a repo, make scoped changes, verify them, commit, push, and hand off clean pull requests.
- Ara workspace surfaces that keep agent work visible without forcing users to manage browser tabs, terminals, and files by hand.
- Memory and skills that help agents reuse what worked before while avoiding stale task-by-task notes.
- Safer background execution with clearer branch boundaries, better handoff summaries, and stronger guardrails around secrets and production systems.

## Next

These are planned next-step improvements for the near term.

- More agent types for repeatable operating work: inbox triage, founder follow-ups, research briefs, release notes, analytics digests, QA passes, and customer-support preparation.
- Stronger developer workflows: automatic test discovery, richer code review context, preview links where available, and better recovery when a background run hits unrelated failures.
- Platform integrations that connect agents to the systems founders and operators already use, including GitHub, Linear, Slack, email, Notion or docs, Stripe, PostHog, Sentry, Supabase, Vercel, and Railway.
- Better routine scheduling so users can turn a one-off successful run into a monitored recurring agent with a clear owner, cadence, and success criteria.
- More transparent run history: what changed, what was verified, what was skipped, and what the agent learned for next time.

## Later

These are larger platform directions we expect to build toward after the core loops are reliable.

- Shared team agents that can run with team-specific permissions, memories, and review policies.
- A reusable agent library for common founder, developer, growth, support, finance, and product workflows.
- Deeper Mac automation for apps and desktop workflows that do not expose clean APIs.
- Richer evaluation and observability for long-running agents, including quality checks, regression tracking, and escalation paths.
- More ways to package, share, and improve agent skills across projects without leaking private context.

## How we prioritize

Ara prioritizes capabilities that make agents more useful in production, not just more impressive in demos. The main filters are reliability, user control, transparency, integration depth, and whether a workflow saves meaningful time when repeated.
