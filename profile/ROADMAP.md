# Ara public roadmap

Ara is building a Mac-native agent workspace for people who want software and operations to keep moving while they stay in control. This roadmap summarizes what we are prioritizing for power users, developers, and founders building real automations.

For the canonical public product page, see [ara.so/roadmap](https://ara.so/roadmap). This GitHub roadmap focuses on the direction most relevant to Ara users who follow the product in public and want to understand what is coming next.

## Now

Ara already focuses on end-to-end agent work: understanding the user's workspace, operating across local files and connected tools, preserving useful context, and turning repeated workflows into reusable skills.

Current priorities are reliability, transparency, and making agent runs easier to trust:

- clearer background-agent handoffs for coding tasks, documentation tasks, and product maintenance
- stronger memory and skill loops so Ara learns from successful runs without asking users to repeat context
- tighter GitHub-centered workflows for branches, commits, pull request handoff, review, and release support
- better workspace visibility so users can inspect what an agent changed, why it matters, and how to test it

## Coming next

### More agent types

We are expanding the kinds of work Ara can own from start to finish:

- developer agents for bug fixes, tests, refactors, docs, release prep, and repository hygiene
- founder/operator agents for inbox follow-up, investor/customer research, internal updates, and lightweight analytics
- growth/product agents for landing page iteration, launch prep, feedback synthesis, and experiment tracking
- personal workflow agents that connect local knowledge, browser research, and recurring desktop routines

### Platform enhancements

The platform is moving toward more dependable, inspectable automation:

- richer skills that capture working procedures, validation steps, and project-specific conventions
- better long-running background work with resumable state, cleaner progress updates, and reviewable artifacts
- multi-agent workstreams for splitting research, implementation, review, and verification across focused agents
- stronger evaluation loops so repeated automations can be measured, improved, and safely reused
- smarter runtime routing so each task can use the right model, tool surface, and execution mode

### Integrations

Ara will keep expanding around the tools builders already use:

- GitHub and code-hosting workflows for issues, branches, pull requests, reviews, releases, and profile health
- developer platforms such as Vercel, Railway, Supabase, Sentry, PostHog, Stripe, and Linear
- knowledge sources such as docs, notes, browser sessions, customer conversations, and internal project memories
- communication surfaces for Slack-style updates, founder follow-ups, and digestible status reports

## Timeline horizons

Roadmaps change as the product and user needs evolve, so Ara uses horizons instead of brittle launch dates.

Near term: make background coding and documentation agents more reliable, easier to review, and easier to hand off.

Next: broaden agent templates for developer, founder, product, and growth workflows, with better setup paths for recurring automations.

Later: support more autonomous multi-agent loops that can plan, execute, evaluate, and improve recurring work while keeping users in control.

## Operating principles

Ara's roadmap is guided by a few product principles:

- Agents should do useful end-to-end work, not just generate suggestions.
- Users should be able to inspect outputs, diffs, memories, and handoffs before trusting automation.
- Each run should make the next run better through skills, memory, and project knowledge.
- Automation should respect user control, local context, and clear review boundaries.

If you are building with Ara and want to shape the roadmap, follow [ara.so](https://ara.so) and share the workflows you want Ara to own next.
