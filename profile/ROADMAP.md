# Ara Public Roadmap

Ara is built for people who want software work to keep moving while they stay focused on direction: power users automating their Mac, developers shipping code, and founders turning repeated operations into reliable agent workflows.

Ara's product site at [ara.so](https://ara.so) describes the current vision for proactive software engineering agents. This profile roadmap makes the near-term product direction explicit for users and builders following Ara on GitHub.

## What Ara does today

Ara runs agent work from your Mac with local context, browser surfaces, coding worktrees, reusable skills, memory, and connected app plugins. The goal is end-to-end execution: understand the task, operate the right tools, verify the result, capture what worked, and reuse that learning next time.

## Now: make agent work dependable

Near-term work focuses on making Ara feel trustworthy for everyday agent runs.

- Stronger background coding agents that create isolated worktrees, validate changes, push review-ready branches, and hand off concise PR context.
- Clearer run visibility across plans, logs, diffs, browser surfaces, and final artifacts so users can audit what happened without reading raw tool noise.
- Better skill capture so successful procedures become reusable playbooks instead of one-off prompts.
- More predictable memory controls for profile facts, project conventions, and durable preferences.

## Next: planned agent types

Ara's roadmap centers on agents that own complete workflows instead of narrow prompts.

- Developer agents for bug fixes, tests, docs, refactors, release prep, dependency upgrades, and code review follow-ups.
- Product and growth agents for landing pages, onboarding experiments, analytics reviews, changelogs, launch assets, and customer feedback synthesis.
- Founder/operator agents for investor updates, recruiting pipelines, CRM hygiene, inbox triage, meeting follow-ups, and recurring weekly reviews.
- Research agents for competitive scans, technical investigations, vendor comparisons, market maps, and source-backed briefs.
- Personal automation agents for repeatable desktop, browser, file, and knowledge-work routines.

## Platform enhancements

Ara is moving toward a runtime where users can start with a natural-language goal and gradually harden the result into a dependable automation.

- Multi-agent workstreams that split broad goals into focused background tasks with clean handoffs.
- Evaluations and smoke tests for agent skills so automations improve without silently drifting.
- Runtime routing across fast, careful, local, and specialized models based on task risk and context size.
- Safer sandboxing for code, browser, file, and app operations with clearer boundaries between draft work and user-owned state.
- Better artifacts: PRs, reports, dashboards, replayable sessions, and saved routines that are easy to review and rerun.

## Integrations on the roadmap

Ara will keep expanding from the tools builders already use.

- Developer platforms: GitHub, local repositories, CI systems, issue trackers, deployment providers, observability tools, and package managers.
- Product systems: Linear, Slack, Notion-style docs, analytics, support queues, feedback sources, and launch channels.
- Business systems: email, calendars, CRM, spreadsheets, billing, data warehouses, and file drives.
- Knowledge sources: project docs, previous sessions, design assets, code history, customer notes, and saved skills.

## Timeline horizons

Roadmap timing is intentionally expressed as horizons rather than fixed launch dates.

- Current focus: dependable background coding, transparent run review, memory and skill quality, and smoother GitHub handoff.
- Coming next: more agent templates, richer integrations, multi-agent coordination, and stronger evaluation loops.
- Later: team-shared agent libraries, deeper admin controls, broader desktop automation, and enterprise-grade governance.

## Operating principles

Ara's roadmap is guided by a few durable principles.

- Agents should finish useful work, not just describe what a user could do.
- Users should be able to inspect, interrupt, and improve every recurring automation.
- Skills and memory should reduce repeated instruction without hiding important context.
- Integrations should make workflows more reliable while keeping user control clear.
- Transparency should build confidence: plans, diffs, outputs, and limitations should be visible enough to review.
