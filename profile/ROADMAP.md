# Ara public roadmap

Ara is building a Mac-native agent workspace for people who want software, operations, and everyday workflows to keep moving while they stay in control. This roadmap is written for external users and contributors who want to understand what we are focused on next.

Last updated: Q2 2026. Ara reviews this roadmap quarterly and updates it as product priorities change.

## Now

Ara already helps users design, run, and refine agents that can work across local context, connected apps, browser research, files, codebases, and recurring workflows. The current focus is making those agent runs reliable, inspectable, and easy to hand off.

Near-term priorities:

- clearer background-agent handoffs for coding, documentation, research, and product maintenance
- stronger memory and skill loops so repeated workflows improve without users re-explaining context
- tighter GitHub workflows for branches, commits, pull request handoff, reviews, and releases
- better workspace visibility so users can inspect what changed, why it matters, and how to test it

## Coming next

### More agent types

Ara is expanding the kinds of work agents can own from start to finish:

- developer agents for bug fixes, tests, refactors, documentation, release prep, and repository hygiene
- founder and operator agents for follow-up, research, internal updates, lightweight analytics, and recurring admin work
- product and growth agents for launch prep, feedback synthesis, landing page iteration, and experiment tracking
- personal workflow agents that connect local knowledge, browser research, and daily desktop routines

### Platform enhancements

The platform is moving toward more dependable, reviewable automation:

- richer skills that capture proven procedures, validation steps, and project-specific conventions
- better long-running background work with resumable state, cleaner progress updates, and reviewable artifacts
- multi-agent workstreams for splitting research, implementation, review, and verification across focused agents
- stronger evaluation loops so repeated automations can be measured, improved, and safely reused
- smarter runtime routing so each task can use the right model, tool surface, and execution mode

### Integrations

Ara will keep expanding around the tools builders already use:

- GitHub and code-hosting workflows for issues, branches, pull requests, reviews, releases, and repository health
- developer platforms such as Vercel, Railway, Supabase, Sentry, PostHog, Stripe, and Linear
- knowledge sources such as docs, notes, browser sessions, customer conversations, and project memories
- communication surfaces for updates, follow-ups, digests, and handoff summaries

## Timeline horizons

Roadmaps change as the product and user needs evolve, so Ara uses quarterly horizons instead of brittle launch dates.

Near term: make background coding and documentation agents more reliable, easier to review, and easier to hand off.

Next: broaden agent templates for developer, founder, product, and growth workflows, with better setup paths for recurring automations.

Later: support more autonomous multi-agent loops that can plan, execute, evaluate, and improve recurring work while keeping users in control.

## Operating principles

Ara's roadmap is guided by a few product principles:

- Agents should do useful end-to-end work, not just generate suggestions.
- Users should be able to inspect outputs, diffs, memories, and handoffs before trusting automation.
- Each run should make the next run better through skills, memory, and project knowledge.
- Automation should respect user control, local context, and clear review boundaries.

If you are building with Ara and want to shape the roadmap, follow [ara.so](https://ara.so) and share the workflows you want Ara to own next.
