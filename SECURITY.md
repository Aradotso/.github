# Security Policy

Ara welcomes responsible reports for security issues in this GitHub organization profile repository.

## Contact

Email security reports to founders@ara.so. Please include enough detail for us to reproduce the issue, including affected URLs, screenshots or proof-of-concept steps when safe, and any assumptions you made.

For serious findings that may belong in Ara's broader security intake, researchers may also use Ara's HackerOne program: https://hackerone.com/ara.

## Scope

This policy applies only to this GitHub organization profile repository and its public profile content, such as profile documentation, images, links, and repository metadata surfaced through the Ara GitHub organization profile.

This policy does not cover the Ara application, Ara desktop clients, Ara cloud services, production infrastructure, customer data, or any non-profile repositories. If you believe a finding affects the Ara product or infrastructure, report it through the contact above or the HackerOne program so it can be routed to the correct team.

## Responsible disclosure timeline

We aim to acknowledge reports within 7 days and will keep reporters updated as we investigate. Our standard disclosure window is 90 days from a validated report to remediation before public disclosure, unless a shorter or longer timeline is mutually agreed based on severity, active exploitation, or remediation complexity.

Please do not publicly disclose details before Ara has had a reasonable opportunity to fix the issue or before the agreed disclosure date.

## Out of scope

The following are out of scope for this repository:

- Social engineering, phishing, or physical attacks against Ara employees, contractors, partners, or users.
- Denial-of-service or resource-exhaustion testing, including DDoS, stress testing, or automated high-volume scanning.
- Spam, SEO manipulation, brand impersonation, or reports about third-party accounts not controlled by Ara.
- Vulnerabilities that require compromised user devices, rooted/jailbroken devices, or malware on a user's machine.
- Reports about Ara product behavior, application vulnerabilities, production systems, or customer data that are not caused by this GitHub organization profile repository.
- Issues in third-party services unless they directly expose a security weakness in this profile repository.

## Safe harbor

We will not pursue legal action for good-faith security research that stays within this policy, avoids privacy violations or service disruption, and is reported promptly to Ara. If you are unsure whether testing is allowed, contact founders@ara.so before proceeding.
