# Contributing to Ara

Thanks for your interest in contributing to Ara projects. This repository provides the organization-level baseline used by public Ara repositories.

## How to contribute

1. Open an issue or discussion before starting broad changes.
2. Keep pull requests focused and easy to review.
3. Include clear context, screenshots, or links when changing docs or brand assets.
4. Follow repository-specific setup and test instructions when contributing to product code.
5. Be kind, direct, and constructive in reviews.

## Pull request expectations

Pull requests should include:

- A concise summary of the change
- Any relevant test, preview, or verification steps
- Linked issues or context when applicable
- Notes about compatibility, migration, or rollout risk when relevant

## Governance baseline changes

Changes to organization-wide files such as `SECURITY.md`, `CODE_OF_CONDUCT.md`, `LEGAL.md`, `LICENSE`, branding assets, and `CODEOWNERS` should be reviewed by Ara maintainers because downstream repositories may reference this baseline.

## Security issues

Report suspected vulnerabilities privately using the process in `SECURITY.md`.
