# Contributing

Thanks for helping improve Ara. This repository sets the organization baseline for how contributions are handled across Ara public repositories.

## Before you contribute

- Read the repository README, LICENSE, LEGAL.md, SECURITY.md, and CODE_OF_CONDUCT.md.
- For security issues, follow SECURITY.md instead of opening a public issue.
- Confirm that your contribution is original or that you have the right to submit it to Ara.

## Contribution workflow

1. Open an issue or discussion when the change is substantial or changes product direction.
2. Keep pull requests focused, reviewable, and tied to a clear problem statement.
3. Include tests, documentation updates, or validation notes when relevant.
4. Follow repository-specific development commands and commit conventions.
5. Wait for maintainer review before assuming a change will be accepted.

## Contribution license

By submitting a contribution, you grant Ara a perpetual, worldwide, irrevocable, royalty-free right to use, reproduce, modify, distribute, sublicense, and commercialize the contribution as part of Ara products, services, and repositories. You represent that you have the rights needed to grant this permission.

Ara may request a separate contributor agreement for some workstreams. If requested, the agreement must be completed before the contribution can be merged.

## Maintainer decisions

Ara maintainers may close issues, request changes, defer work, or decline contributions when they do not fit product direction, quality standards, security requirements, or legal constraints.
