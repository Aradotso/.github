# Contributing

Thanks for helping improve Ara. Most Ara repositories are proprietary, so contributions are accepted at Ara's discretion and under the repository license unless a separate written agreement applies.

## Before contributing

- Check the repository README, open issues, and existing pull requests before starting work.
- For substantial changes, open an issue or discussion first so maintainers can confirm scope.
- Do not submit confidential information, secrets, customer data, generated credentials, or third-party proprietary code.

## Pull request expectations

- Keep changes focused and reviewable.
- Explain the problem, solution, and test coverage in the pull request description.
- Include screenshots, recordings, or logs only when they do not expose private information.
- Follow the repository's existing style, tooling, commit conventions, and release process.
- Update docs when behavior, setup, governance, or public APIs change.

## Development quality

Run the relevant formatter, linter, typecheck, build, and tests before requesting review. If a check cannot be run locally, note why in the pull request.

## Code of conduct

All participation in Ara projects must follow `CODE_OF_CONDUCT.md`.
